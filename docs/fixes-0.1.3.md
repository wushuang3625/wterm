# wterm 0.1.3 — ProxyJump、系统 agent 与 SFTP 队列

## 连接方式

先保存跳板连接，再在目标连接的“跳板链”填写其名称，例如 公司跳板,生产跳板；也可使用 alice@jump.example:2222,bob@[::1]:2200。裸地址使用目标连接的用户名和系统 agent；需要不同认证方式时先建立跳板 Profile。SSH config 中的明确 Host 别名也可引用，保存的 Profile 优先。

每一跳校验它自己的 known_hosts 指纹，并在认证窗口显示当前主机。循环引用和超过 8 跳会在建立连接前拒绝。复制标签、自动重连、导入配置和 SFTP 都保留路由信息；同一主机通过不同跳板链连接时不自动混用传输。

“系统 ssh-agent”读取本机公钥并由 agent 签名，不再伪装成默认私钥文件探测。Windows 使用 OpenSSH named pipe；Unix 使用 SSH_AUTH_SOCK。不可用、没有普通公钥、签名失败或超时均明确报错。私钥认证与密码认证仍可选择，MFA 保留原多轮流程。agent 证书身份、Pageant 和 agent forwarding 暂未支持。

## SFTP

- 上传（选择文件或拖入）与下载（另存为）进入队列；进度、速度与错误按任务展示。
- 最多 2 项并发，同会话同一路径上传串行，避免同时截断同一目标。
- 当前流可以暂停/继续，也可取消；失败或取消后可确认覆盖并从头重新传输。
- 上传已有远程文件需要确认；新目标以排他创建方式打开，防止检查后出现同名文件时静默覆盖。
- 任务固定会话、源和目标，切换面板不会改变传输路径。关闭会话会取消相关任务。
- 支持八进制 chmod；可选跟随终端目录，依赖远程 Shell 上报目录。
- Windows 远程编辑使用 notepad.exe 打开下载副本，避免服务器文件名进入 cmd/start 或触发可执行文件关联。

暂停不等于跨连接断点续传。取消/失败可能留下部分文件；重试会从头覆盖。队列暂不跨应用重启保存。递归目录传输、文件拖出、压缩解压和持久化断点续传仍待后续实现。

## 验证范围

使用独立 Node ssh2 服务端、临时生成的密钥及独立 agent 协议服务。验证双跳通道、agent 签名后两轮 MFA、认证失败/取消，以及通过跳板进行真实 SFTP 二进制往返与覆盖保护。复制引擎测试验证暂停继续及阻塞 I/O 取消；前端测试验证队列并发、重试、会话隔离与操作竞态。

界面测试使用 Edge 和模拟 Tauri 接口，不代替原生窗口或真实服务器验收。尚需实测 Windows 系统 agent 服务、实际 JumpServer 的 direct-tcpip 策略、多跳 MFA、真实远程编辑回传，以及不同平台/服务端兼容性。
